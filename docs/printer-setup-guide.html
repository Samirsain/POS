One PC runs the connector. Only one.

There is a single print queue, and whichever connector claims a job first gets it. A second connector on a laptop with no printer will take receipts and fail them — which is exactly how an afternoon was lost to Opening COM9: File not found while the printer sat on a different laptop's cable.

What you need

Nothing is downloaded and nothing is installed from a disc.

  • The printer, its power supply, and the USB cable.
  • A roll of 58 mm thermal paper.
  • The POS Printer Connector folder, copied from the project's dist/. It carries its own node.exe and your Supabase keys, so the laptop needs no Node, no npm and no configuring.
  • Administrator rights, once, for the setup step.

You do not need the printer's own driver disc. Receipts are sent as RAW ESC/POS bytes, so Windows' built-in Generic / Text Only driver carries them through untouched.

Setting the laptop up

Six steps, once per laptop.

  1. Load the paper the right way up

    Only one side of thermal paper takes an image, and a roll put in backwards feeds perfectly while printing nothing at all. Scratch the paper hard with a fingernail: the side that goes dark is the side that must face the print head.

    Close the lid until it clicks. A lid that is merely resting shut makes the printer ignore everything sent to it.

  2. Plug the cable in and switch the printer on

    Straight into the laptop, not through a hub. The power light should be steady, not blinking — blinking is out of paper or lid open.

  3. Run Setup printer.cmd as administrator

    Right-click it in the connector folder and choose Run as administrator. It needs those rights because adding a printer and moving a port both do.

    It finds the port the printer actually came up on, then either moves an existing queue onto that port or creates one with the Generic / Text Only driver, and prints a test slip.

  4. Read the slip, not the screen

    A queue accepting bytes is not paper. This is the step that tells you the truth:

    Slip USB SETUP OK printed Done. Go to step 5.
    Blank Paper moved, nothing on it The roll is in upside down. Take it out, turn it over, run the setup again.
    Still Nothing moved at all The printer is not taking data. Check the power light, the lid, and try another USB port before anything else.

  5. Start the connector

    Double-click Start Printer Connector.vbs. It runs with no window on purpose — there is no terminal for anyone to close by accident. What it is doing is written to connector.log beside it.

  6. Make it survive a reboot

    Run Run at startup.cmd once. It puts a shortcut in this user's Startup folder.

    To undo that later — and you must, on any laptop that stops being the printer's laptop — delete POS Printer Connector.lnk from:

    %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup

Printing, day to day

Once the laptop is set up, nobody touches it again.

Open the website on any device, fill in the four fields, press Print. The receipt number comes from the database, so two people printing at the same moment cannot collide. The receipt comes out of whichever laptop is running the connector.

On an Android phone there is a second button, Print on this phone. The phone drives the printer itself over Bluetooth through the free RawBT app, so no laptop needs to be awake at all. Pair the printer once in Android's Bluetooth settings — the PIN is 1234.

On an iPhone, and in Firefox or Safari on a desktop, the connector is the only route. iOS cannot reach this printer directly: it speaks Bluetooth Classic only through MFi-certified accessories, and this is not one.

Two small things that are normal and not faults: the screen shows ₹ where the paper shows Rs., because the printer has no rupee glyph; and there is no auto-cutter, so the paper is torn by hand against the bar.

When something goes wrong

Look up the exact words you were given.

Opening COM9: File not found

A connector on the wrong laptop claimed the receipt. It went looking for the Bluetooth COM port, and that laptop either has no Bluetooth or is not the one holding the printer.

Stop the connector on every laptop except the printer's, and delete its Startup shortcut. Then reprint from the Queue.

USB printer Windows would use: none found

The connector can see no printer on a live USB port. Either the printer is not enumerating, or its queue is pointed somewhere else.

Open connector.log. If the queue is on the wrong port the log names it and gives you the one command that fixes it — that case is common enough that the connector refuses to print rather than write into a port with nothing behind it.

"POS-58-Series (1)" is on port Printer PORT:, but the printer is on USB002

The queue and the cable have drifted apart. The vendor's installer creates its queue on a private Printer PORT: monitor that is attached to nothing, and Windows renumbers the printer to USB003 and up after a replug. Both look completely healthy: Windows accepts every receipt, drains the spooler, and the paper stays blank.

Run the command the log prints, or just run Setup printer.cmd again:

Set-Printer -Name "POS-58-Series (1)" -PortName "USB002"
No Printer Attached

Windows' own words for a printer port with nothing answering on it. The device node exists; the printer behind it does not respond.

This is a hardware state, not a settings problem. Power, lid, cable, another USB port — in that order.

Receipt saved but not printed

The receipt number is safe. It is in the database and nothing is lost; only the paper is missing.

Fix the printer, then open Queue and press Reprint on that receipt. Reprint is deliberate and logged as a second copy — which is why Retry refuses to touch a job already marked successful.

Paper comes out blank

Almost always the roll, in upside down. Feeding works from either side; printing does not.

The test that settles it without a computer: switch the printer off, hold the FEED button, switch it on. That prints the printer's own firmware page. If that is blank too, it is the paper or the head, and nothing in the software can matter.

Commands worth knowing

Run these from inside the connector folder, where node.exe lives.

CommandAnswers
node.exe connector.js --portsWhich COM ports exist, and which Windows printer the connector would use over USB.
node.exe connector.js --testPrints a slip through whichever route is live, USB or Bluetooth.
connector.logEvery job claimed, the route it took, and why any of them failed.

At startup the log records the route in one line — printer: POS-58-Series (1) (USB), or printer: COM9 for Bluetooth, or NOT FOUND. If that line is missing entirely, the folder is an old build from before USB support; copy a fresh one.

Why it works this way

The short version, for whoever inherits this.

A web page cannot reach a USB thermal printer on Windows. usbprint.sys binds itself to any USB printer-class device and will not release it, so the browser is refused the handle — measured on this printer, which comes up as USB\VID_0456&PID_0808\PRINTER owned by USB Printing Support. Getting round that needs a driver swap with Zadig, an administrator, and the loss of the Windows print queue, repeated on every laptop.

But that same driver holding the device is what gives Windows a print queue for it — and a program running on the machine may push RAW bytes into that queue, which reach the port without the driver rendering anything. So the cable is handled by the connector, which is already on the machine, and the browser is never asked to do something it cannot.
